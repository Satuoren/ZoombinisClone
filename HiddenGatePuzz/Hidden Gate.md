### How an action becomes evidence of CT

| CT skill | Player does | Game logs | Proxy metric |
| --- | --- | --- | --- |
| Decomposition | Splits four features into single questions | Features that differ between consecutive tests | One-change-at-a-time tests (%) |
| Pattern recognition | Spots what crossers share and turned-back bloops lack | Whether each test could still split the rules left standing | Tests that narrowed the possibilities (%); redundant tests |
| Abstraction | Replaces a list of cases with one general rule | Submitted rule compared with the hidden rule on all 108 bloops | Correct on first guess; equivalent rules accepted |
| Algorithmic thinking | Runs a repeatable test sequence | Order of tests and the draft rule at test time | Strategy label; confirming vs. challenging tests |
| Debugging | Fixes a wrong rule after a counterexample | Wrong guesses and draft edits after each | Wrong guesses per gate; draft edits |
| Transfer | Reuses the same logic on new features | Gate 3 and gate 5 share logic, no shared features | Tests at gate 5 vs. gate 3 |

### Does it really measure CT? Open questions

- Every metric above is a behavioral proxy. None is shown to be CT until it is checked against something outside the game.
- Content check: ask two or three CT researchers to map each metric to a CT definition and mark the ones that do not fit.
- Convergent check: compare gate scores with a validated CT test or Bebras-style items from the same players.
- Think-aloud check: watch five players and confirm that "one change at a time" reflects intent, not luck.
- Reliability: gates 3 and 5 have the same logic, so a player's tests should be similar on both. Large gaps point to feature difficulty or noise.
- Confounds to rule out: lucky guesses, prior Mastermind-style experience, color perception, and attention.
